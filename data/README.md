# SciNet Release Data

Flat, self-contained CSV exports of the SciNet taxonomy and tasks.

## Files

| File | Description |
|------|-------------|
| `tasks.csv` | Every task in the hierarchy. Columns: `task`, `category`, `level`, `domain`, `field`, `subfield`, `expert_input`. Level is one of "universal" (applies to all researchers), "domain" (e.g. Social Sciences), "field" (e.g. Economics), or "subfield" (e.g. Labor Economics). Higher-level columns are empty when a task belongs to a broader level. `expert_input` names the researcher whose review produced the wording and is empty otherwise — the same flag the website shows as a gold seal. `category` is the category of the universal task the task rolls up to in `task_activity_assignments.csv` (see [WORK_ACTIVITIES.md](../WORK_ACTIVITIES.md)); before September 2026 it came from the pre-roll-up hierarchy, which left Design & Development with only its universal task. |
| `substeps.csv.gz` | How each task decomposes into the steps a researcher performs. Columns: `level`, `domain`, `field`, `subfield`, `task`, `substep_id`, `substep`. Gzipped; `pandas.read_csv` reads it directly. |
| `task_time.csv` | How long each task takes, estimated separately for every subfield it appears in. Columns: `task`, `level`, `domain`, `field`, `subfield`, `n_substeps`, `researcher_hours` (attended effort), `elapsed_hours` (including unattended waiting), `confidence`. |
| `task_ratings.csv` | Importance, reach, and frequency of each task, rated separately for every subfield it appears in, on O\*NET's scales. Columns: `task`, `level`, `domain`, `field`, `subfield`, `importance` (1–5), `pct_researchers` (0–100, share of researchers in the subfield who do it at least occasionally — this is O\*NET's "Relevance of Task" scale, which they publish as a 0–100 share), `frequency` (1 = yearly or less to 7 = hourly or more), `classification` (`Core` if `importance` ≥ 3 and `pct_researchers` ≥ 67, else `Supplemental`). |
| `task_prevalence.csv` | Observed share of a subfield's papers that perform each task, read from full text — the empirical yardstick for the ratings. Columns: `field`, `subfield`, `task`, `n_papers`, `n_involved`, `prevalence`. Subfield-level tasks in 316 subfields only. |
| `task_dimensions.csv` | Every task scored on five families of dimensions (see [TASK_DIMENSIONS.md](../TASK_DIMENSIONS.md)). One row per row of `tasks.csv`, in the same order. Join on `task`, `level`, `domain`, `field` and `subfield` together, or by row position: 235 task texts appear in more than one subfield and carry different scores in each, so joining on `task` and `level` alone fans the rows out. Columns: `relation_*` (aggregate, evaluate, produce, communicate, support), `medium_*` (information, materials, people) and `mode_*` (theoretical, quantitative, qualitative, design, none) are 0–100 shares that sum to 100 within each family, except in 18 rows where the medium shares sum to less than 100 because the model used a category outside the schema; `cognitive_complexity`, `physical_deployment`, `regulatory_restriction` are the CDR levels 0–4; `rl_physical_gate_pass` (0–1), `rl_verification`, `rl_simulability`, `rl_feedback_density` (1–10) are from the RL Feasibility Index; `pasteur_applies` (yes/no), `pasteur_understanding`, `pasteur_use` (1–5, empty when it does not apply), `pasteur_quadrant` (Bohr, Edison, Pasteur, neither, n.a.); `years_education` (0–20). `cdr_rl_source` is `substep_mean` for every scored task: the CDR and RL values are the time-weighted mean over the task's substeps in `substep_dimensions.csv.gz` (`task` would mark a direct task-level rating, no longer used). The CDR and RL cells are empty for the 2 tasks that have no decomposition in `substeps.csv.gz`; the other empty cells are model refusals on the task-level families. |
| `substep_dimensions.csv.gz` | The CDR and RL scores of every substep in `substeps.csv.gz`: one row per substep with the same keys (`level`, `domain`, `field`, `subfield`, `task`, `substep_id`) and the columns `cognitive_complexity`, `physical_deployment`, `regulatory_restriction` (0–4), `rl_physical_gate_pass` (1 pass, 0 fail), `rl_verification`, `rl_simulability`, `rl_feedback_density` (1–10). The task-level values in `task_dimensions.csv` are the time-weighted means of these rows. Empty cells are 89 model refusals plus 3 answers whose JSON could not be read for the CDR columns, and 75 refusals for the RL columns. Gzipped. |
| `work_activities.csv` | The 140 work activities, with names, one-paragraph descriptions, the universal task each sits under, and `n_tasks`. See [WORK_ACTIVITIES.md](../WORK_ACTIVITIES.md). |
| `task_activity_assignments.csv` | Which work activity each domain-, field- and subfield-level task belongs to. One row per distinct task text and level, 6,956 rows, so a text performed in several subfields is assigned once. |
| `topic_frame_overlay.csv` | Extra OpenAlex topics added to a subfield's sampling frame where the crosswalk alone gave too few eligible papers. Columns: `field`, `subfield_slug` (lowercase, `&` written as `and`, other characters as `_`), `topic_id`, `topic_name`, `confidence` (high or medium), `reason` (model rationale, truncated), `n_papers` (eligible papers for that topic). Additive only: it never moves a topic out of its home subfield. |
| `work_activity_dimensions.csv` | The same dimensions for each of the 140 work activities: the simple mean over the tasks assigned to the activity in `task_activity_assignments.csv` (a task text that appears in several subfields is first averaged over its placements, so each assigned task counts once). The numeric dimension columns of `task_dimensions.csv`, plus `activity_id`, `universal_task_id`, `universal_task`, `category`, `activity_name`, `n_tasks`, `pasteur_applies_share`, and `n_tasks_scored`, the number of assigned tasks carrying CDR scores. It does not carry `task`, `level`, `domain`, `field`, `subfield`, `pasteur_applies`, `pasteur_quadrant` or `cdr_rl_source`. Seven activities have one fewer task scored on the relation, medium, mode and Pasteur families than `n_tasks_scored` shows. |
| `openalex_topic_subfield_mapping.csv` | Maps each OpenAlex topic to its display domain, field, and subfield. Columns: `topic_id`, `topic_name`, `domain`, `field`, `subfield`. |
